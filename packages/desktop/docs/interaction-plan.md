# 대화와 작업 개입 계획

2026-09-08. 범위는 Desktop과 기존 CLI RPC가 제공하는 대화 흐름이다.

## 흐름

요청 작성 → 접수 → 실행(추가 지시/후속 작업) → 필요 시 사용자 답변 대기
→ 선택·확인·입력·편집 응답 전달 → 실행 계속 → 완료 또는 중단/오류.
연결 오류 → 명시적 재연결과 저장된 세션 복원. 불확실한 요청은 자동 재전송하지 않는다.

## 구현 계약

- Main이 요청의 원본 ID와 선택값을 보관한다. Renderer에는 표시용 값과 일회용 ID만 제공한다.
- select/confirm/input/editor는 자동 취소하지 않고 요청 카드로 제공한다. 선택값은 미리 선택하지 않는다.
- Desktop 내장 `desktop_ask_user` 확장을 각 CLI에 연결한다. 에이전트가 직접 질문 카드를 요청하며 선택형의 직접 입력도 지원한다. 전역 설정은 변경하지 않는다.
- confirm의 거절과 요청 취소를 구분한다. 본문은 실행하지 않는 텍스트로 표시한다.
- 중복/이미 종료된/다른 대화의 응답은 거절한다. 서버 timeout을 반영하고 연결 종료/중단에서 요청을 폐기한다.
- 사람의 답변을 기다리는 동안 일반 RPC 시간 제한으로 연결을 실패시키지 않는다. 응답은 RPC 명령의 응답 ACK를 기다리지 않는 별도 프로토콜이다.
- 승인 전 기다리는 것은 확장 기능이 요청한 작업에 한정된다. 모든 도구에 대한 권한 게이트를 새로 만들지는 않는다.
- notify/status/widget/title/editor text도 텍스트로 표시한다. 제안된 입력은 사용자가 적용하며 기존 초안을 덮어쓰지 않는다.
- 실행 중 기본 전송은 추가 지시로 바뀐다. 명시적 후속 작업, 대기 목록, 전송 실패 초안 보존을 제공한다.
- 사이드 채팅에도 동일한 카드/개입/상태를 적용한다. 숨겨진 사이드 채팅의 답변 대기를 앱에 표시한다.
- 기록과 대기 요청은 앱 메모리에서 관리한다. 재시작 후 오래된 승인 요청을 재사용하지 않는다.

## 검증

오프라인 RPC fixture로 모든 응답 형식, 동시 요청, 긴 대기, 중복 응답,
중단·만료·연결 종료·재연결을 검증한다. Renderer와 IPC 검사를 추가하고,
최종 패키징 앱에서 본 대화/사이드 채팅을 실제 키 입력으로 확인한다.
실제 모델 과금 호출은 하지 않는다. TUI custom UI 등 RPC가 제공하지 않는 기능은 범위 밖이다.

구현과 검증 결과는 [검증 결과](verification.md)의 대화·작업 개입 항목에 기록한다.
