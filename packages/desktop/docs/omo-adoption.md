# OMO 기술 도입 — Prime Desktop 0.10.2

2026-09-09. 기준 소스는 [oh-my-openagent 8bd0c35](https://github.com/code-yeongyu/oh-my-openagent/tree/8bd0c35b3ba532ab0cb0df49ea71467303aa92ba)입니다.
Native/Senpi, OpenCode, Codex판을 구분해 조사했고 Prime CLI의 공개 확장·RPC에 맞는 기술을 이식했습니다.
[전체 조사와 원본 코드 링크](omo-adoption-research.md)는 검토 당시 후보까지 포함합니다. 아래 표가 최종 구현 범위입니다.

## 구현한 기능

| 기능 | 실제 제공 범위 |
| --- | --- |
| 백그라운드 작업 | 본 대화와 별도 Prime 프로세스·세션, 역할별 작업 등록, 진행 상태·최근 도구 내역·결과 표시 |
| 작업 의존성 | 선행 작업 완료 후 실행, 선행 결과를 다음 작업에 전달, 실패한 선행 작업 대기, 최대 3단계 하위 위임 |
| 실행 관리 | 기본 다른 프로젝트 2개 병렬, 설정 1–4개, 같은 프로젝트의 worker는 직렬, 미완료 32개 기본/최대 100개 |
| 역할과 모델 | 일반·탐색·조사·계획·구현·리뷰·화면·검증 8개 역할, 실제 Prime 모델 목록에서 선택, 모델·추론 수준·시도 기록 |
| 사용자 개입 | 시작 과정의 질문까지 포함한 선택·확인·입력·편집 카드, 추가 지시, 하위 작업 포함 중단, 명시적 재개 |
| 복구·업데이트 보호 | 작업·세션·결과를 로컬에 저장, 재시작 시 중단 표시와 대기열 정지, 미완료 작업이 있으면 업데이트 설치 차단 |
| 해시 기반 편집 | OMO 해시·줄 포맷 헬퍼 사용, LINE#HASH와 SHA-256 digest, 겹침·오래된 내용 거절, BOM/CRLF 유지, 임시 파일 교체 |
| AST 검색 | 실제 ast-grep 네이티브 파서, TS/TSX/JS/HTML/CSS 구조 검색, 파일·결과 크기 제한 |
| LSP | 패키지에 포함한 TS/JS 언어 서버, 정의·참조·심볼·진단·rename 미리보기, 호출별 서버 정리 |
| 프로젝트 기억 | 프로젝트별 제목·내용·근거 저장, 검색·수정·삭제, 200개 제한, 알려진 비밀 값 거절, 앱 종료 시 저장 대기 |
| Skills | OMO 공통 17개 모두 Prime용 진입점으로 재작성, 기존 15개와 합쳐 32개 기본 활성화, 원본 문서·고지 보존 |
| 공개 MCP | Context7 문서와 grep.app 코드 검색 기본 등록, 사용 시 연결, 사용자가 수정·삭제한 설정 보존 |

에이전트에 제공되는 도구는 기존 `desktop_ask_user`, `desktop_mcp`에
`desktop_tasks`, `desktop_code`, `desktop_ast`, `desktop_lsp`, `desktop_memory`를 더한 7개입니다.
Prime 전역 설정이나 OMO 설치·인증을 변경하지 않습니다.

## 사용

1. **⇧⌘J** 또는 **작업 패널 → 에이전트 작업**을 엽니다. 단축키는 패널 설정에서 변경할 수 있습니다.
2. **새 작업**에 요청·역할·완료 기준을 넣고 필요하면 선행 작업을 선택합니다.
3. **실행 설정**에서 모델과 한도를 조정합니다. 값 변경은 이후 시작하는 작업에 적용됩니다.
4. 작업 세션은 일반 대화 목록과 분리해 두 프로세스가 같은 기록을 여는 일을 막습니다. 작업 행을 선택해 질문에 답하거나 추가 지시를 보냅니다. 결과는 **대화에서 결과 검토**로 본 대화에 넣을 수 있습니다.
5. **프로젝트 기억**에서 장기 보관할 규칙과 출처를 관리합니다. 에이전트도 해당 프로젝트 범위에서 같은 저장소를 사용합니다.

예시 요청: “관련 코드를 탐색하고 구현한 다음 독립 검토 작업을 이어서 등록해줘. 각 작업에 완료 기준을 넣고 결과를 확인해줘.”
실행 완료는 모델 턴 종료를 뜻하며, 완료 기준이 자동으로 승인되었다는 의미가 아닙니다.

## 동작 경계

- 앱이 실행된 동안의 백그라운드 작업입니다. 앱 종료 후 resident daemon이나 외부 OMO peer에 붙는 기능은 없습니다.
- 작업 파일은 본 대화·사이드 채팅과 공유합니다. 직렬화는 이 작업 관리자의 같은 프로젝트 worker끼리 적용하며, worktree 격리나 모든 외부 프로그램과의 파일 잠금은 아닙니다.
- 선행 관계는 기존 작업 ID만 허용합니다. worker가 만든 같은 프로젝트 하위 작업은 현재 worker가 끝난 후 시작하므로 worker 안에서 그 하위 작업을 기다리지 않습니다.
- 응답 시간 기본 한도는 30분이며 설정 범위는 1–120분입니다. 연결·세션 초기화 후부터 측정하며 사용자 답변 대기도 포함됩니다. 금액/토큰 예산이 아닙니다.
- 모델 fallback과 불확실한 쓰기 자동 재시도는 없습니다. 수동 재개는 기존 세션을 사용하고 이미 발생한 효과를 먼저 검토하도록 안내합니다. 호출 결과가 불확실하면 작업 목록부터 확인해야 하며 생성 요청의 영구 idempotency key는 없습니다.
- 전체 작업 기록은 500개 제한입니다. 현재 기록 삭제·보관 UI와 무제한 장기 저장은 제공하지 않습니다.
- 해시 검증과 마지막 읽기 확인은 오래된 편집을 거절하지만 타 프로세스와의 마지막 검사/rename 사이까지 원자적인 CAS를 보장하지 않습니다. 전체 OMO hashline 편집 엔진의 완전한 복제는 아닙니다.
- AST 도구는 검색 전용이고 LSP 이름 변경은 미리보기입니다. 편집은 내용을 검토한 후 별도 편집 도구로 수행합니다. LSP 기본 지원은 TS/JS이며 다른 언어 서버는 별도 연결이 필요합니다. push 진단의 빈 목록은 전체 프로젝트 통과 증거가 아닙니다.
- 기억은 명시적인 사실 저장입니다. OMO의 Git 기반 identity·자동 reflection·장기 학습 엔진을 구현한 것은 아닙니다. 알려진 비밀 패턴 외의 모든 문자열을 자동 판별하지 못합니다.
- OMO 전용 팀 mailbox/resident supervisor, Boulder/ULW 자동 반복 hooks, 모든 Native 전용 Skill, 자동 post-edit formatting/comment checker, OpenCode TUI/tmux 호환층은 포함하지 않습니다. 계획·실행·검토 절차는 Prime용 Skills와 작업 그래프로 제공합니다.
- 원본 Skill 문서는 배경 참고 자료이며 원본의 스크립트·외부 디자인 자료·브라우저 엔진을 설치하지 않습니다. Aside 우선 흐름을 사용하고 원본의 쿠키 추출·stealth 엔진·텔레메트리는 도입하지 않았습니다.

## 검증

- 21개 테스트 파일 **130개 통과**, Biome·TypeScript 검사, arm64 빌드·패키징 통과.
- 실제 `.app`에서 기존 대화·첨부·MCP·터미널·패널과 새 작업 등록·선행 의존성·질문·추가 지시·중단·업데이트 차단·재시작 복원을 검증했습니다. renderer/console 오류 없음.
- 설치된 Prime CLI 0.9.3의 실제 확장 로더가 도구 7개와 Skills 32개를 읽고 TypeBox 스키마를 컴파일했습니다. 패키지 내 AST 네이티브 바인딩·해시 편집·LSP 정의 조회도 실행했습니다.
- 단위 테스트에서 실제 TS 언어 서버의 TS2322 진단, 정의/rename 미리보기, 파일 불변을 확인했습니다. 가짜 서버의 성공 응답으로 대체하지 않았습니다.
- Context7의 `resolve-library-id`/`query-docs`, grep.app의 `searchGitHub`를 실제 공개 MCP에서 발견했습니다. 도구 목록만 조회했으며 사용자 프로젝트·인증은 전송하지 않았습니다.
- 모델 대화는 격리된 가짜 CLI로 검사했습니다. 유료 모델 호출은 없었고 실제 모델의 도구 선택·결과 품질 평가는 미검증입니다.
- Vite의 500KB 초과 renderer 번들 안내와 packager의 새 `.icon` 형식 생략 안내는 남습니다. 기존 ICNS 아이콘과 실제 터미널 렌더링은 검증했습니다.

## 산출물·출처

검증 앱은 `out/omo-adoption/Prime Desktop-darwin-arm64/Prime Desktop.app`입니다.
배포는 `desktop-v0.10.2` 버전 릴리스와 `desktop-stable` 서명 채널을 사용합니다.
기존 설치는 앱 안에서 업데이트하면 같은 경로를 유지하므로 Dock 재등록이 필요하지 않습니다.
별도 테스트 앱의 0.10.1 → 0.10.2 교체와 대화·초안 복원을 검증했습니다. [업데이트 보고서](../.smoke/update-iEnmF6/report.json).

원본 SUL과 개별 MIT 고지는 `vendor/omo` 및 각 Skill에 포함됩니다. [복사 파일·SHA-256 목록](../vendor/omo/manifest.json),
[변경 고지](../vendor/omo/NOTICE.md), 배포의 `THIRD_PARTY_NOTICES.txt`를 유지합니다.
개인 사용 범위로 구현했으며 앱의 MIT 표기로 원본을 재허가하지 않습니다.
