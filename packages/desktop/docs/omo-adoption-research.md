## 2. Native RPC and reuse of the full extension

**Source evidence supports RPC operation, but does not prove compatibility with Prime's existing transport.** For ordinary arguments the Native launcher prepends --extension <native-package>/plugin and forwards the remaining arguments to Senpi, so --mode rpc reaches the engine with OMO loaded. OMO's own child runner explicitly constructs --mode rpc launches; tests also contain RPC cases. The Senpi engine implementation is an external pinned dependency and was not inspected or executed here. Package-registry/browser retrieval failed in this environment; exact Senpi command/event parity remains a parent-side verification item. [Launcher][launcher], [child spawn][rpc-spawn], [spawn tests][rpc-tests]

The full extension can conceptually run **inside Senpi while Prime supplies the UI**, provided a Senpi-specific external transport and session model are implemented and verified. It cannot be assumed to run inside Prime merely because both accept a --mode rpc flag. The base extension requires on/registerFlag/getFlag/registerTool/registerCommand/sendMessage/sendUserMessage; missing capabilities disable it. Task registration additionally requires registerMessageRenderer. Some components use optional rpc, events and registerMcpServer, plus Senpi-specific session/model/context surfaces. Component registration errors are caught, so a successful process start can conceal partial feature registration. [Composition][compose], [API seam][api], [task capability gate][task-surface]

## 5. Minimal hashline vendoring and correctness boundary

Exact extraction candidates are hashline-core/src/hash-computation.ts, constants.ts, xxhash32.ts and file-text-canonicalization.ts. The full hash-computation file imports hashline-chunk-formatter.ts for streaming, so copying it unchanged is not a four-file closure. Either retain that dependency or explicitly extract only the non-streaming functions with a modification notice. The JS xxHash32 fallback means Bun is not required for the computation itself. [Hash][hash], [constants][hash-constants], [xxHash][xxhash], [canonicalization][canonical]

Current line hashes strip carriage returns and trailing whitespace; legacy hashes strip all whitespace. Alphanumeric lines use seed zero, other lines use line number; result is reduced to 256 two-character codes. Therefore it is a short edit anchor, **not a collision-proof file/version integrity check**. Canonicalization strips/restores BOM and normalizes line endings; restoration uses one detected LF/CRLF style, not exact preservation of mixed endings. A Prime adapter must enforce fresh reads, range validity, conflict/stale detection, authorized path boundaries and write ownership independently. Test CRLF/BOM, Unicode, punctuation-only/blank lines, changed content with hash collisions, malformed anchors and concurrent edits. These are proposed acceptance cases, not tests run here. [Hash][hash], [constants][hash-constants], [canonicalization][canonical], [upstream validation][hash-validation]

No separate permissive license was found for hashline-core in this tree: treat OMO-derived extraction as covered by the root license unless a more specific grant is established. A small copy and a rewritten adapter do not erase the copied portion's license. [Root license][license], [package][hash-pkg]

## 7. Implementation handoff and acceptance evidence

1. **App task/DAG service:** own durable IDs, parent/project/session binding, allowed file scope, requested/resolved model category, graph version, dependencies, attempt IDs, delivery receipts and evidence paths. Rehydrate interrupted states as uncertain/interrupted until reconciled with the owned Prime sessions; never blindly replay a prompt or completed write. Prime's documented no-replay behavior and OMO's idempotent workflow semantics support this boundary. [Prime baseline][prime-architecture], [workflow][dag]
2. **Lifecycle:** distinguish prompt acceptance, running, waiting for user, cancellation requested, terminal result and verification outcome. Use existing InteractionStore/AgentManager routing; app quit is not a guarantee of resident execution. Required evidence: DAG ordering/concurrency, cross-owner denial, message dedupe, worker dialog routing, cancellation while queued/running, crash/restart reconciliation, model-unavailable behavior and report links. These are implementation acceptance criteria, not research verification results. [Prime baseline][prime-architecture], [task RPC][task-rpc]
3. **Skills and references:** import reviewed source material as references; expose 17 adapted wrappers only when their prerequisites are met. Retain separately licensed material, exclude unresolved engine payload, report absent frontend submodule content. Avoid changing user's provider/auth/global OMO/Codex settings. [Shared source][shared-tree], [attribution][frontend-notice], [browser attribution][browser-notice]
4. **MCP templates:** OMO's Codex .mcp.json supplies grep_app (https://mcp.grep.app), context7 (https://mcp.context7.com/mcp), git_bash and LSP local runtime commands. These are pinned configuration examples, not verified live endpoints. Local relative dist paths are not valid Prime package paths without staging. AST MCP is a separate Native component. Start templates unconnected; prove initialize/list-tools and representative authorized operations separately. [MCP config][codex-mcp], [AST component][ast-component]
5. **Evidence report:** separate existing, implemented-and-verified, implemented-unverified, template/reference-only, native-only/deferred and license-excluded. Include source and local revision, actual commands/results, unavailable prerequisites, known risks and non-covered features. Do not use “all OMO ported” for worker orchestration + hash helpers + Skill wrappers.

Research verification: local pinned-source inspection, manifests, component registry, RPC adapters, selected host-assumption sections for all 17 Skills, full cited license/attribution texts and gitlink inventory. No install, build, test, model invocation, runtime launch, secret read, global configuration change or code edit. External Senpi engine source/runtime, remote endpoint availability, complete generated Native tarball, every nested Skill reference and transitive-license closure remain unverified.
